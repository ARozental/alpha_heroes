## 8. Insights and lessons

1. **One 48-game evaluation can't judge a deploy.** One PC eval is about ±0.11 at 2 se. Identical Mac arms differed by 1.5–1.7 se three times. Paired, pinned-map, side-by-side replicates are the minimum instrument, and trends come from replaying checkpoints under fixed code.
   - Evidence: 22:15 halves (+0.146 vs +0.003); 22:44 and 01:20 null pairs; 06:07 replay.
   - Confidence: high.
2. **The random map generator makes "same seed" tests unpaired.** VCMI's RMG gives a different map per run. Pin the map files, or every A/B compares different maps.
   - Evidence: 19:59.
   - Confidence: high.
3. **Check that a diagnostic can tell signal from noise before trusting it.** Compute the pure-noise value under the actual optimizer schedule. With repeated passes over one batch, Adam's |m|/√v reads 0.31 on pure noise. The "signal ratio" had been read as evidence for weeks.
   - Evidence: 10:17–10:19.
   - Confidence: high.
4. **Battle-level RL on few, long, correlated battles is mostly noise per update.** About 0.5% signal; the value gradient rests on ~4 games. Weight by independent outcomes, not decisions. The developer's rule fits: "an explanation must have predicted the failure".
   - Evidence: 10:23; 06:31 games_by_weight 48→66, V spread 0.0021→0.0009.
   - Confidence: medium-high (early readings).
5. **Imitation labels from a scripted AI encode its follow-through, not your situation.** NK2's GATHER and its danger-ignoring moves are right for NK2's plan and wrong for ours. Once our priors made our heroes shelter, NK2's labels sat on night-penalized entries at 6.7% of decisions against 0.9% before.
   - Evidence: 19:00; 05:55.
   - Confidence: high.
6. **Learnable prior corrections drift where the teacher pushes.** night_gain fell in 21 of 23 updates from the teacher's cross-entropy while reward was silent. Before letting a correction learn, check which loss term actually drives it (per-term push readings).
   - Evidence: 23:01.
   - Confidence: high.
7. **Changing a feature the trained network reads can backfire.** The weights respond to the new input distribution: in-town heroes took more danger, 0.098→0.110. Inject new knowledge as additive logit priors the network can outvote.
   - Evidence: 19:28.
   - Confidence: medium.
8. **Fixing one failure path often moves the failure.** The hero-night prior cut hero-first eliminations 14→5, and eliminations moved to emptied towns (2→11 "together"). Trace how players actually go out after each fix.
   - Evidence: 02:23, 04:52.
   - Confidence: medium (one replicate trace; three-replicate scores).
9. **Bounded relative units aren't automatically better.** Dividing gold by empire value under-priced late hero losses: eliminations 30→43. The developer's own "too small" worry predicted it. Normalize by something fixed per game, or test at the late-game horizon.
   - Evidence: 00:45.
   - Confidence: medium.
10. **Measure before building; let expected gain veto mechanisms.** Night-power step two, the unseen-kill memory prior and the night-label drop were not built or left off, each with numbers. That saved deploy slots and kept one change per deploy.
    - Evidence: 01:20, 01:24, 06:00.
    - Confidence: high as practice.
11. **Don't deploy a risky label change right before an unobserved window.** Have a PC-side auto-stop. GATHER landed 20 minutes before the developer went offline; the collapse ran 9.5 h unseen. A score-driven teacher weight amplified it as a positive feedback loop.
    - Evidence: 08:48, 09:08, 18:03, 19:00.
    - Confidence: high.
12. **Engine guardrails tuned for an untaught model become constraints once it learns.** The 8-decision exchange cap, set on Nov 1, cut 14% of deliveries after the span taught stack-by-stack delivery. Re-audit caps when behaviour changes.
    - Evidence: 08:38.
    - Confidence: high.
13. **Fixing a waste behaviour can expose another.** Removing meeting loops turned burned movement into idle movement (0.095→0.269), not into useful moves. Track the conserved quantity (movement points), not only the symptom.
    - Evidence: 03:08–03:16.
    - Confidence: high.
14. **AI-assisted development: two sessions reviewing each other with written predictions beat either alone.** Both also produced confident wrong mechanisms (b1's "empties towns"; e5's "slides"; b1's Adam drift argument), so every story needs a falsifying measurement.
    - Evidence: throughout.
    - Confidence: high.
15. **A memory note doesn't fix a recurring behaviour.** The "your decision" habit recurred three times despite the note (19:39). Placement and wording changes followed; compliance in this window was good.
    - Confidence: medium.
16. **Fork: an AI summarizing a project for an audience drifts toward generic ML framing.** Log transforms; "14 action types" as a challenge. It also fabricates illustrations, and the developer had to restate the project's real principles. The developer's design questions in that context (MOVE across levels; unseen exits) produced a real modelling fix and the night's best single gain (+0.059).
    - Evidence: fork 17:02, 13:21; deploy 53.
    - Confidence: medium-high.
